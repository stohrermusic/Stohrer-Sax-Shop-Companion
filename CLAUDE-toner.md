# The Analyzer (the Toner until 2026-11-10)

The tab is called Analyzer and opens on the intonation chart; the harmonic analyzer is behind the HARMONICS switch, experimental. The code, the settings keys (`toner_*`, `visible_tabs["Toner"]`, `toner_unlocked`) and the file names keep the old name. Architecture mirrors the tuner:

- `toner_engine.py`: Pure audio/math — FFT with 16384-sample window (~2.7 Hz resolution), fundamental detection via peak-picking with harmonic series verification (a sub-harmonic candidate must show its own peak plus harmonics at multiples coprime to the divisor — see "Pitch reading" below), temporal hysteresis, harmonic extraction up to 20th harmonic (noise floor cutoff at -60 dB) with parabolic amplitude correction and Hann closed-form frequency, spectral centroid computation, descriptor computation (complexity, warmth). `TonerEngine` manages its own sounddevice input stream independently from the tuner. Preset storage uses `load_tone_presets()`/`save_tone_presets()` with `TONER_DATA_FILE` (`toner_data.json`, auto-migrated from old `tone_profiles.json`).
- `toner_tab.py`: All tkinter UI — `TonerTabMixin` builds the tab: the top area is one of two frames (`_toner_show_harmonics`): the chart frame (a white `tk.Canvas` drawing `intonation_chart` primitives, with Compare... and Export... under it) or the harmonics frame (spectrum canvas left, intonation gauge + note display right); the control strip (bottom) carries the VIEW / SCALE / FPS / SENS / HARMONICS switches, the sax selector, Load..., MODE (free / guided) and Capture; its first row (`_toner_strip_row1`) holds the switches and the selector, and the right column (`_toner_strip_right`) is packed into that row, or under it when the screen cannot take one row (`_toner_strip_two_rows`, decided by main's `_widen_for_analyzer` from the one-row need). The strip's German labels are kept short so one row fits a 1024 px screen on Windows fonts (Matt, 2026-11-11: abbreviate rather than widen; "keine Voreinst.", "Aufnahme"; one row needs 1003 px in German, 933 in English, 973 es, 1023 fr, 995 it, measured 2026-11-11); tooltips keep the full words. A new strip label gets a German translation no longer than it need be. Preset management, comparison tool with multi-select and filtering, import/export.
- The toner auto-starts/stops when switching tabs, same as the tuner.
- Same three mechanisms as the tuner engine and tab (see CLAUDE-engines.md "Strobe Tuner"): numpy and sounddevice imported separately; `TonerEngine.synthetic_hz` feeds a Bb3-with-harmonics tone for tests and the CI tours (`test_toner_live`); `_toner_error_state` is redrawn after `_toner_build_spectrum_bars` wipes the canvas.

- There are no live descriptor gauges. Descriptors feed only the Analyze tool, where deltas between presets cancel mic and setup confounders; the right side of the live tab is the intonation gauge and note display. Why they were removed: `docs/decisions/toner.md`.

- Two comparison descriptors (shown in Analyze tool, not live gauges): Even/Odd Ratio (even vs odd harmonic balance), Rolloff Shape (nonlinearity of harmonic rolloff — spectral peaks/bumps). Even/Odd defaults to on (proven most robust across recording conditions); Rolloff Shape defaults to off. Configured in Options > Settings > Analysis tab.
- Population percentiles: The Analyze tool computes `compute_population_stats()` for all presets of the same sax type and shows percentile rankings (P0-P100) alongside descriptor values. Interpretive labels: low/below avg/mid-range/above avg/high. Out-of-range notes are flagged using `SAX_NOTE_RANGES` in toner_engine.py.
- Comparison analysis includes harmonic-range interpretation: H1-H4 shifts = bore, H7-H13 shifts = neck/mpc, broadband = mpc/player. Same-player comparisons noted as more reliable.
- Scale toggle switches between linear (default, true amplitude ratios) and dB (logarithmic).
- Spectrum overlay: a preset can be loaded as a ghost overlay on the live spectrum (via Analyze > single preset or group average > Overlay on Spectrum). Blue ghost bars update per-note as you play. All live descriptor gauges (delta and absolute) have been removed — the analyze tool (both sides averaged) is where comparison actually works.

## Pitch reading

- Frequencies come from `audio_utils.hann_peak_freq`; levels (`peak_mag` with its parabolic amplitude correction) are deliberately unchanged, so `harmonics_db` and every descriptor stay comparable with stored captures.
- Sub-harmonic verification counts only multiples coprime to the divisor (`gcd(mult, divisor) == 1`), with the requirement one lower. **Don't "simplify" it to skipping only `mult == divisor`**: measured, that reads octaves high.

Gated by Tests 20 and 21 in `test_toner_engine`. Measurements: `docs/decisions/toner.md`.

## Capture rules (2026-11-10)

- **Whole-window frames only.** A frame reads the last `WINDOW_S` (0.37 s) of sound. A capture averages only the frames whose whole window lies inside the note: `toner_engine.whole_window(times, first, last)`, `first + WINDOW_S <= t <= last - WINDOW_S`. Free mode gathers every frame of the held note with its time and filters at save; calibration keeps a frame from `WINDOW_S` after the recording started and, when the note stops inside the 5 s, drops the frames whose window reaches past its last sound; `analyze_audio_file` applies the same rule per segment. There is no attack skip any more (`ATTACK_SKIP_FRAMES` is kept for the record, nothing reads it). A free note must be held about 1.1 s (34 frames at 30 fps) to be kept; shorter is remembered in `_toner_too_short` (concert note, seconds, frames kept), shown by no UI yet.
- **The clock is audio time.** `TonerEngine.audio_time_s` counts the samples the input handed over since `start()` (the callback's frames; 1024 per `analyze()` on the synthetic source); the capture machine's countdown, recording and frame times read it through `_toner_clock()`, never `time.time()`. On a microphone the two agree; a WAV fed faster than real time counts the same seconds. Capture `timestamp`s stay wall-clock strings.
- **A calibration capture is filed under the note asked for** (`note` the asked note's concert name, `written_note` the asked name, `detected_as` what the detector heard most, in display pitch), as before the port.
- Stored captures are raw data and were not touched; the read side (`compute_fingerprint`, the chart) recomputes from them. New captures average fewer frames than old ones (no onset, no release), so a capture made before 2026-11-10 is not frame-for-frame comparable with one made after; its pitch is now exact on a steady tone (A3 read -1.09 c before).

Tests: `test_toner_live` (the tab's state machine on fabricated frames), `test_toner_data` (storage, migrations, fingerprint and descriptor goldens, the file analyzer). History: `docs/decisions/toner.md`.

## Intonation (the Analyzer's chart data)

`intonation.py` is pure: `run_from_preset(preset, reference_hz, session_indices)` / `run_from_captures(sessions, sax_type, reference_hz)` give an `IntonationRun` of `NoteReading`s (written name in this app's spelling, register 1 to written C#5 and 2 above, takes), each capture one `Take` with its cents against equal temperament at the reference pitch; a note's cents are the **median** of its takes; `note_spreads` (median, lowest, highest, count) and `overlay(runs)` (the union of notes low to high, registers, one line of points per run) are what the chart draws; `register_changes` where the dashed line goes. **A take that is not its note is never drawn** (2026-11-10): a take whose pitch is further than `OFF_NOTE_CENTS` (50, half a semitone: beyond it the take is nearer another note) from its labelled note at the run's reference pitch is left out and counted in `left_out["off_note"]`, before the fingerprint's plausibility filter (`left_out["implausible"]`; a label nobody can read is `"unlabelled"`). **The one correction** (`corrected_label`, Matt: "Correct for sure"): a label exactly two transpositions below the pitch, within the bound, whose corrected note lies in the horn's range (the storage mistake of six presets from 2026-03-23/25) is re-labelled on read and counted in `IntonationRun.corrected`; an octave above that again is the detector's slip and stays out; nothing else is ever re-labelled, and in Matt's library it touches no take outside those six presets. Read-side only, like the fingerprint's filter: nothing on disk changes. **The fingerprint applies the same correction** (Matt, 2026-11-11: "Yes, apply it"): the rule is `toner_engine.corrected_label`, applied to a capture by `toner_engine.corrected_capture`, the one place; `compute_fingerprint` calls it before the plausibility filter and `run_from_captures` calls it before the off-note check, so the chart and every fingerprint reader (per_note, population percentiles, the Analyze tables, the spectrum overlay, the group average) group a March take under the note it is. `intonation` re-imports the rule and the pitch helpers (`A4_HZ`, `OFF_NOTE_CENTS`, `midi_to_hz`, `cents_from_equal_temperament`) from the engine; the engine never imports `intonation`. Do not write the rule a second time anywhere. In Matt's library it moves 506 captures in the six March presets and nothing else; the measured before and after: `docs/decisions/toner.md`, round 10. The tab turns the counts into one plain line under the chart (`_toner_chart_footnote`, the `footnote` of `chart_primitives`, so the export carries it) and says "No take matched its note." when nothing is left. Why 50: in Matt's library the furthest kept take is 49.7 cents off and the nearest left-out one 112 (`docs/decisions/toner.md`, round 4). `offset_and_shape` and `low_register_offset` exist for a later ask; nothing shows them (Matt: the chart shows cents as played, nothing else). Tests: `test_intonation`.

## Recording Quality

`compute_rolloff_rate()` measures harmonic rolloff (dB/harmonic). The live warning uses `get_rolloff_threshold(mic_type, sax_type)`, which depends on both (ribbon 3.5, dynamic 2.8, alto with dynamic 3.5, condenser the base `ROLLOFF_WARN_THRESHOLD`); both call sites pass sax_type. Suppressible per preset; stored per session and in fingerprints; the comparison tool warns on a mismatch. Readings per mic: `docs/decisions/toner.md`.

## Mic Type/Model

`mic_type` (condenser/ribbon/dynamic/other, required) and `mic_model` (required) are preset fields, same as mouthpiece and reed. Sessions snapshot mic from the preset at creation time. The control strip shows the loaded preset's mic info. Comparison tool filters by mic type and warns on mismatches. Migration: presets without mic fields get backfilled from their sessions' most common mic_type on first load.

## Analyze Tool

File > Analyze...: one preset, a two-preset delta or a multi-preset spread, with population percentiles (`compute_population_stats()`) and a Character Map. The window and the Group Report are non-modal and deliberately not transient (a transient loses the maximize button on Windows). Detail: `docs/decisions/toner.md`.

## Mutate Preset

Duplicates a preset with all fields pre-filled (name cleared), letting users change one variable (mouthpiece, mic, reed) and save as a new preset. Streamlines A/B testing workflows.

## Settings Dialog

Options > Settings opens a tabbed dialog (General: input device, recording, pitch, the intonation chart's "Low notes on the left"; Analysis: preset fields, descriptor visibility). Capture Threshold stays as a standalone menu item due to its live level meter.

## Capture Performance

During free-mode capture, JSON saves are deferred to every 10 seconds (`_toner_schedule_save`) instead of after every micro-capture. A cached `_toner_captured_notes` set avoids per-frame iteration over captures for the note counter. Both prevent progressive lag during long sessions. `_toner_flush_save()` is called on capture stop to ensure data is persisted. The app-exit path (`_toner_save_settings()`, called from `on_exit`) also flushes any in-flight free-mode micro-capture and persists the active session, so exiting mid-capture loses nothing — and it merge-updates `toner_settings` rather than replacing it, so keys owned by the Settings dialog (like `analysis_descriptors`) survive exit.

## Capture Modes

Two selectable capture modes, the MODE switch's free / guided (the values stay "free" and "calibration"): "free" (continuous micro-captures while playing naturally, one per held note; the default) and "calibration" (guided chromatic scale Bb3-F6, 5s per note, labels from guide not detector, stores `detected_as` field for detector accuracy analysis). Which frames of a note count, and the clock: "Capture rules" above. A separate "file" method (import WAV via File > Presets > Import Audio File) extracts stable note segments offline. Each capture is tagged with its method.

## Auto-Transposition

SAX selector sets both the break frequency and the displayed note names. Written pitch is shown by default (alto shows A4 when concert C4 is played). "Concert" checkbox overrides to concert pitch.

## Coverage Summary

Dialog appears after stopping a capture session, showing a bar chart of note distribution colored by register (low/mid/high), gap assessment, and a "Resume Capturing" button to fill underrepresented registers.

## Fingerprinting

`compute_fingerprint(sessions, sax_type)` recomputes descriptors from raw harmonics (never uses stored descriptors), averages per-note first (equal weight per note), then across notes. This prevents register skew.

## The file path (WAV analysis)

`toner_engine._file_windows` reads a WAV once (16/24/32-bit PCM and float, any rate, mono or stereo) and runs every window through `analyze_buffer`; `analyze_audio_file` names runs of windows by ear (a segment per note the detector heard, whole-window frames only, `FREE_MIN_FRAMES`) and `_file_capture` averages one into a capture; `analyze_asked_notes` reads a guided run's recording again under the names ASKED for, each note from its own stretch `wav_start_s`..`wav_end_s` (a note played 60 cents flat keeps its name; by ear it lands on its neighbour). Since 2026-11-10, with `level_dbfs` (dB against full scale; `mean_level_dbfs` for a capture) on every result and capture. A guided capture made while a WAV is recorded carries `wav_start_s` / `wav_end_s` on the recording's clock (`TonerEngine.recording_time_s`, which starts at `start_recording`); the session's WAV re-analysis uses the asked names when every capture has them. The progress callback reports every 200 windows and once at the end with the exact total. Measured on the recordings corpus (2026-11-10): a 4x zero-padded peak estimator and this app's Hann closed form agree within 0.01 cents on known tones and the Hann form costs 250 times less, so the rule against a zero-padded FFT stands (`docs/decisions/toner.md`, round 5). Tests: `test_toner_data` (generated WAVs: a scale, a note 60 cents flat asked and by ear, an octave-prone timbre, a short note, silence, 16/24/32-bit and float), `test_toner_live` (the stretch fields).

## WAV Recording

Enabled by default. On first capture, the app prompts the user to choose a recording folder (no silent default). The `recording_file` field in the session dict links the WAV to its session. Filenames use preset name + timestamp at save time for uniqueness. WAV reanalysis is automatic when recording is on — the offline `analyze_audio_file()` pipeline replaces live captures at session end. The offline analyzer uses stricter segment detection (attack skip, minimum stability frames) producing roughly 2x the accuracy of live free-capture (20 harmonics extracted vs ~12 live). Takes ~5 seconds for a 4-minute recording. "Delete WAV after analysis" optionally removes the file afterward. Progress is shown in the capture bar. Disabling WAV recording shows a warning about reduced accuracy.

## Sandbox Mode

Enabled via Options > Settings > Analysis > "Allow sandbox mode". Sandbox presets (`"sandbox": true` in JSON) relax all field requirements except preset name — no mic type, sax type, or instrument fields required. Designed for non-sax instruments, contact mics, effects chains, or experimental setups. The sandbox flag is immutable once sessions exist. Visual indicators: `[sandbox]` prefix in preset list, amber "sandbox" mic label, `[sandbox]` in capture bar, yellow banner in analyze tool. Comparison between sandbox and regular presets shows a warning. A "sandbox (concert pitch)" checkbox on the control strip appears when sandbox mode is enabled and forces concert pitch display.

## Tone Preset Data Model

Presets use nested library format: `{library_name: {preset_name: preset_data}}`. A preset saves setup details (horn + player + mouthpiece + reed + mic type + mic model) and pre-fills session metadata for quick capture start. Sessions store their own copy of the metadata at creation time.

**The Key heights link** (2026-11-11; Matt: "link a horn to an entry in the key heights library", "that link belongs to the preset"): an optional preset field `key_heights`, `{"library": L, "set": S}` or None, naming one entry of the Key Heights library (`key_height_library.json`, the one store). Read through `toner_engine.key_heights_link` (anything unreadable is none; presets from before the field load as none, no migration writes anything); the entry through `key_heights_entry`; a session snapshots `key_heights_snapshot` at creation (the link plus a copy of the entry's `units` and `heights`, the link alone when the entry is already gone), so a run keeps what the horn was set to if the entry is later edited, renamed or deleted. On the form (`_toner_build_preset_fields`): a readonly picker, "(none)" first, then every set of every library as "set (library)", a linked entry that is gone listed and marked missing; never required, in either mode, sandbox or not; Mutate pre-fills it like every field; the collector writes it. Beside it **Enter heights...** (`_toner_enter_key_heights`): the Key Heights tab's own fields (`ALL_KEY_HEIGHT_FIELDS` as the Key Layout shows them, `library_features.key_height_fields_shown`) with its mm/inches conversion (`library_features.convert_height`), saved as a NEW set through `save_presets(..., KEY_PRESET_FILE)` into `app.key_presets`, the tab's lists refreshed, the set picked. New sets only: a horn whose heights change gets a new set and a mutated preset (Matt); editing stays on the Key Heights tab. Nothing about key heights is drawn on the chart, the legend, the export, the harmonics side or the Analyze tool (Matt: name the preset so the horn is recognisable). Import and export carry the field and the snapshots as any other; `unwrap_tone_import` does not know it. Tests: `test_toner_data`, `test_analyzer_tab`.

A preset contains sessions (date + captures). **Captures store only raw measurement data** — no pre-computed descriptors:

- `harmonics_db`: list of dB values relative to fundamental (up to 20 harmonics, index 0 = fundamental)
- `harmonic_cents`: list of cents deviations from ideal harmonic positions
- `fundamental_freq`: detected fundamental frequency in Hz
- `spectral_centroid`: amplitude-weighted center frequency of the harmonic series (Hz)
- `signal_level`: RMS signal level at capture time (0.0-1.0)
- `note`: concert-pitch note name
- `method`: "free", "calibration", or "file"
- `n_frames`, `timestamp`, and other metadata

Descriptors (complexity, warmth) are always computed on the fly by `descriptors_from_harmonics()` using current formulas. This means formula improvements apply retroactively to all historical data. Old captures with baked-in `descriptors` fields still load fine — stored descriptors are ignored.

`compute_fingerprint(sessions, sax_type)` in `toner_engine.py` aggregates all sessions: averages harmonics per-note, computes descriptors from the averaged harmonics, then averages descriptors across notes with equal weight. The `per_note` dict maps note names to averaged harmonic data, enabling note-by-note comparison across horns.

**Read-side capture filter** (`_capture_is_plausible()`): `compute_fingerprint` drops a capture whose note is outside `SAX_NOTE_RANGES[sax_type]` (no altissimo) or whose `harmonics_db` holds a non-finite value or one over +20 dB. It is read-only: never modify raw captures on disk. Why: `docs/decisions/toner.md`. Since 2026-11-11 the March 2026 label correction (`corrected_capture`, see Intonation) runs first, so a corrected note in range is plausible and a detector slip the rule does not cover is treated exactly as before; the fingerprint dict carries `corrected`, the number of captures grouped under a corrected label.

Flat legacy format (presets at top level without library wrapper) is auto-migrated on load.

## Toner Calibration

Preset notes can contain subjective tone descriptions ("rich horn", "very bright", "dark and warm"). The `tools/calibrate_toner.py` script scans all annotated presets, extracts keywords, compares them against computed descriptors, and reports alignment. The `tools/analyze_horn_spread.py` script computes statistical spread of descriptors across all presets — min/max/mean/stddev per descriptor, per-note variation, gauge scaling suggestions, and grouping analysis by horn type and manufacturer. Both tools help identify where the descriptor scaling constants need adjustment. Bias sliders in the UI provide per-user visual calibration without affecting captured data.

**Descriptor calibration status**: complexity (spectral flatness) and warmth (H2 strength) are the descriptors kept. Key constants live in toner_engine.py: `RICHNESS_RAW_MIN`, `RICHNESS_RAW_RANGE`, `WARMTH_DB_FLOOR`, `WARMTH_DB_RANGE`. `tools/profile_report.py` generates a detailed single-preset report. Why brightness, darkness, resonance and fullness were removed: `docs/decisions/toner.md`.
